Chrome extension + local hub

Chat with a coding agent that drives your real browser.

AgentBrowser is a Chrome side panel wired to a local hub. You talk to a coding agent; it clicks, types, reads and navigates in the browser you are already logged into. No automation profile, no re-login. Highlight anything, click Ask.

Why chrome.debugger

Synthetic clicks don't work any more.

Events dispatched from a content script carry isTrusted: false, and modern editors built on Lexical or React composers ignore them outright. That is why so much browser automation silently fails to type into a real text box.

AgentBrowser dispatches through chrome.debugger instead. CDP clicks and Input.insertText arrive exactly as a human's do. Because it attaches to your existing profile, the manifest asks for debugger, tabs, storage, offscreen, sidePanel for the agent loop — plus one small selection watcher (content script) that powers the Ask button and the right-click menu. It never drives the page.

Architecture

One hub between the panel and the page.

Adapters

Bring your own coding agent.

Pick one per chat, or set a default in server/hub/config.json. Six CLIs run one process per turn and resume their own session; two call a provider API directly; two are Claude-native.

claude-agent-sdk

Runs in the hub process. Tools exposed as an in-process MCP server; screenshots come back as images the model can see.

claude-cli

Spawns claude -p in stream-json mode, kept alive for the session. Full Claude Code toolset alongside the browser tools.

codex

codex exec --json, resumed via codex exec resume, MCP attached per invocation.

opencode

opencode run --format json, resumed via -s, MCP through a generated opencode.json.

copilot

copilot -p -s with a deterministic --session-id reused every turn.

grok

grok -p --output-format json, resumed via --resume, MCP through a generated .grok/config.toml.

agy

agy -p, conversation id discovered by diffing the conversations dir, MCP registered merge-only.

gemini

gemini -p -o stream-json, resumed via -r, other MCP servers excluded by name.

anthropic-api

Calls the Anthropic API directly. No CLI needed; the key lives in ~/.agentchat/keys.json at mode 0600.

openai-api

Calls the OpenAI API directly. Same ten browser tools, no file or shell tools.

Any MCP harness

Not on the list? Point it at the proxy.

server/proxy/mcp-proxy.mjs is a stdio MCP server that forwards tool calls to the hub. Anything that speaks the Model Context Protocol gets the same ten tools, with no adapter of its own.

  • Cursor
  • Cline
  • Qwen CLI
  • OpenClaw
  • Hermes Agent
  • Muse Code
  • LangGraph
  • DeepAgents
  • Any MCP client
{
  "mcpServers": {
    "agentbrowser": {
      "command": "node",
      "args": ["/absolute/path/to/agentbrowser/server/proxy/mcp-proxy.mjs"]
    }
  }
}

CLIs take a config in this shape and only the file name differs: openclaw.json for OpenClaw, mcp_servers in Muse Code's settings file, ~/.hermes/config.yaml for Hermes Agent. Python agent frameworks reach it the same way: LangGraph and DeepAgents both load stdio MCP servers through langchain-mcp-adapters.

The one requirement is stdio transport. A client that only speaks HTTP to MCP servers cannot reach the proxy as it stands.

Browser tools

Ten tools, every adapter.

Omit tabId to act on the active tab.
toolargsresult
tabs_list{}every open tab with id, url, title, active
tab_new{url?}the new tabId
tab_close{tabId}confirmation
navigate{url, tabId?}url and title after load, 20s cap
read_page{tabId?, maxChars?}innerText, 60k char default cap
screenshot{tabId?}base64 PNG
click{x, y, tabId?}trusted CDP click
type_text{text, tabId?}inserts into the focused element
press_key{key, tabId?}e.g. Enter, Escape, Meta+A
eval_js{expression, tabId?}the evaluated value

The service worker attaches the debugger on demand, serializes commands per tab, and re-attaches if Chrome detaches it.

Install

Running in about a minute.

$ git clone https://github.com/VasiHemanth/agentbrowser.git
$ cd agentbrowser/server
$ npm install
$ npm start          # listens on ws://127.0.0.1:9010
  1. Open chrome://extensions and enable Developer mode.
  2. Choose Load unpacked and select the repo's extension/ directory.
  3. Click the AgentBrowser toolbar icon to open the side panel.
  4. The status dot turns green when the hub is reachable. Send a message.

Requires Chrome and Node.js 20.11 or newer. MIT licensed.

Before you install

Known constraints.

  • Chrome allows one debugger client per tab. With DevTools open on a tab, tool calls on that tab fail until it detaches.
  • Chrome shows an "is being debugged" infobar while attached. Dismissing it detaches; the next tool call re-attaches.
  • The hub accepts one extension connection. A second Chrome profile displaces the first.
  • Filling a form is not permission to submit it. The agent will not click submit, send, post or buy unless you asked.
  • API keys sit in ~/.agentchat/keys.json in plain text, protected by file permissions, not encrypted.
